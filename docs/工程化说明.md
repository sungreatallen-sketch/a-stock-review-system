## 2. 版本演进规则
- **v1.0**：原始需求 + 定稿架构 + 当前实现（本次封装基线）
- 后续问题/修复/新需求 → 更新 REQ/ARCH/execution_rules.yaml → 版本号递增（v1.1、v1.2…）
- 每次变更：git 提交信息标注版本与变更内容
- 全部重大修复完成后，统一封装版本并打 tag 保存

## 3. 变更流程（用户与系统共同遵守）
1. 用户提出新需求/问题
2. 系统对照 REQ/ARCH/规则，判断是否需要变更
3. 变更内容先落文档与规则（R19），再改代码
4. 合规自检（R20）验证变更后行为
5. git 提交，标注版本

## 3.5 运维约定（防复发）
- **HTML 模板/前端变更**：修改 app/html_report.py 后必须重启 com.ashare.server（常驻进程缓存旧模板）
- **Python 代码变更**：重启 com.ashare.bot / com.ashare.server 以加载新代码
- 重启命令：`launchctl kickstart -k gui/$(id -u)/com.ashare.bot`（或 server）
- 变更后可用 `curl -s http://127.0.0.1:8787/report/<date> | grep 关键片段` 验证服务端实际输出
