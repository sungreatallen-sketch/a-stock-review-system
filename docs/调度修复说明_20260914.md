# 调度与交易日历修复说明 · 2026-09-14

状态：基于用户上传代码制作并完成离线验证的补丁。尚未部署到Mac，未读取本次现场调度日志。不能把测试成功描述为现场已修复。

## 用户已确认的行为

- 保留晚上开机后主动发送“复盘/预测”询问的流程。
- 自动任务仅北京时间交易日16:00后处理当天终版；晚间可以补当天，不跨日自动补旧推荐。
- 明确手动询问仍有回复；成功手动发送完整终版后，当天自动轮询跳过。
- 手动盘前/休市读取已有历史终版，不按今天重新生成历史预测。
- 选股评分、涨停过滤、RSI开关保持现有实现；本次不重算任何历史收益。

## 已确认问题与证据边界

1. auto_review先取最近已收盘日期，16:00限制仅在target==today时生效，周一早晨/休市可以进入历史补发。
2. flag与generated_at完全相等才算发送，报告晚间更新可能让已发送状态失效。
3. utils原2026休市表有错：春节、端午、中秋及元旦范围与交易所公告不同。
4. THS便利函数用hour>=15且minute>=30，错误排除16:00、17:10等时间。
5. 自动重生成之后只检查report_complete，允许日期或终版不合格报告进入发送。
6. workflow手动晚间复用仅检查生成日期，没有要求收盘后终版；旧盘中报告可能被复用。
7. 当前9/11报告和flag都为20:21:41，发送前flag状态/9:10实际触发入口仍缺日志，不能认定此次事件完整根因。

## 实现范围

- app/utils.py：北京时间、统一年度日历、前后交易日与最近已收盘日期，未覆盖年份/回溯失败显式报错。
- config/trading_calendar_2026.json：交易所年度公告离线快照，全年覆盖，无需API联网。不是自动更新服务。
- app/review_delivery.py：统一终版校验，持久化首次发送记录，兼容旧flag，同目录线程/进程互斥。
- scripts/auto_review.py：先检查当日自动执行资格，明确跳过盘前/休市/跨日；保留既有健康检查；失败不发送旧报告。
- scripts/send_review.py：默认自动模式也有门槛，只有显式--manual才能手动查看历史。卡片成功后记录发送；图片失败不重复发送成功卡片。
- app/feishu/bot.py：手动流程共用互斥锁，成功卡片记账，主动再次询问仍正常回复。
- app/workflow.py：手动盘前/休市只读历史；晚间不能复用盘中旧版；采集日期错误停止生成预测。
- app/ths_client.py：交易日期便利函数委托统一日历，保留原交易日API供诊断。
- app/predict/track.py：用同一日历计算T+1/T+2；卖出日15:30前不结算。开盘买、收盘卖公式不变。
- execution_rules.yaml升级为v1.10，仍34条，主要修订R15；AGENTS与工程记忆同步。日志以追加方式并入原文件。
