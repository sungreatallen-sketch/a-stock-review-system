## 经验教训（工程化结论）
1. **外部依赖会变**：端口、域名、限流、网络——必须自动发现/多路兜底/显式上报，不能写死。
2. **一致性靠机制**："用户看到的=结算的""报告完整才复用"靠规则+代码强制，不靠记忆。
3. **合规靠自检**：规则系统能当场抓住未实现缺口与运行时异常（如 I11）。
4. **输出要双口径**：单一口径容易漏信息（开盘 vs 收盘）。
5. **工程基线化**：需求/架构/规则/问题记录全部文档化+git 版本化，变更走流程。
